# Graphic Realism для Personal OS Learning

Источник системы: [Kosetor/graphic-realism-design](https://github.com/Kosetor/graphic-realism-design), версия правил 1.1. Репозиторий доступен по лицензии MIT. Эта инструкция описывает адаптацию для учебного сайта; это контентный продукт, поэтому ему не нужен полный интерфейс агентской консоли.

## Назначение экранов

| Экран | Основная задача | Главное действие | Состояния |
|---|---|---|---|
| Главная | Найти последний материал и понять актуальность данных | Читать статью | загрузка / готово / устаревший снимок / ошибка данных |
| Статья | Прочитать или прослушать материал | Отметить как прочитанное | не отмечено / отмечено / ошибка хранилища |
| Прогресс | Понять статус тем и связи | Выбрать тему | загрузка / готово / ошибка данных; мобильный текстовый режим |

## Визуальная модель

Применяй слои в порядке `Base → Chrome → FX`:

1. Base: текст статьи, данные, ссылки, аудио и кнопки работают без декоративного слоя.
2. Chrome: плоские панели, линия 1 px, радиусы 2–4 px, акцентная полоса, CAPS-метки и моноширинные даты.
3. FX: сетка и MGR-знаки имеют непрозрачность не выше 5–6% и не несут обязательной информации.

Основные токены и переопределения находятся в `site/assets/mgr-theme.css`. Не добавляй новые произвольные hex-цвета в шаблоны. Палитра экрана: volt для главного действия, cyan для ссылок и данных; amber/signal используются только для состояний. Длинный текст остаётся системным UI-шрифтом, заголовки — display, даты и метаданные — mono.

Используемые MGR Geometry assets:

- `site/assets/mgr/ic-crosshair-square.svg` — текущий учебный материал;
- `site/assets/mgr/ic-circle-grid.svg` — граф тем.

Оба взяты из `icons/mgr-geometry/` исходного репозитория. Не добавляй другой набор декоративных иконок в эти панели. Не используй `ic-q-logo.svg`. Новые SVG копируй только после проверки происхождения и лицензии; фиксируй их назначение здесь и в README.

## Адаптивность и доступность

- Интерактивная область не меньше 44×44 px.
- На ширине до 700 px действия статьи занимают строку целиком. Диаграмма прогресса скрывается до 600 px, но полный список тем остаётся доступным.
- Цвет никогда не является единственным обозначением статуса: рядом всегда есть текст.
- Фокус обозначается cyan-контуром толщиной 2 px. Icon-only элементы требуют `aria-label`.
- Соблюдай `prefers-reduced-motion`; смысл страницы не зависит от движения.
- Фоновая сетка и знаки не размещаются поверх основного текста и не снижают контраст.

## Порядок работы hermes_a

1. Перед изменением шаблонов прочитай актуальные `SKILL.md`, `tokens/tokens.css`, `tokens/personal-os.css`, `rules.md`, `agents/personal-os.md` и `icons/mgr-geometry/manifest.json` в `graphic-realism-design`. Не полагайся на старую копию этой инструкции, если версия дизайн-системы изменилась.
2. Перенеси `mgr-theme.css`, подключение стилей и MGR-assets в фактический приватный генератор. Ручная правка только опубликованного HTML будет потеряна при следующей статье.
3. Для каждого экрана сначала запиши задачу, одно главное действие и состояния. Затем проверь Base без FX, добавь Chrome и только потом необязательный FX.
4. Не превращай учебную статью в полноценный app-shell. Rail, topbar и statusbar нужны только если сайт действительно станет многоэкранным приложением с постоянной навигацией и состоянием соединения.
5. Проверь главную, одну короткую и одну длинную статью, страницу прогресса, загрузку и ошибку данных на широком экране и при ширине 390 px. Проверь клавиатуру, видимый фокус, 200% масштаб и reduced motion.
6. Запусти `python scripts/check_site.py` и `node --test tests/*.test.cjs`. После push дождись CI и деплоя того же SHA, затем осмотри Pages. Не объявляй соответствие только по прохождению автоматических проверок.

## Критерии приёмки

- Один главный CTA на экране, остальные действия визуально вторичны.
- Не более двух несемантических акцентов на экране.
- Радиусы панелей не больше 8 px, по умолчанию 4 px.
- Все решения используют токены; исключения документированы.
- На панели не больше одного доминирующего MGR-знака, его декоративная непрозрачность 4–8%.
- Есть рабочие loading/error/empty состояния там, где загружаются данные.
- Контент и управление понятны при отключённых FX и на мобильном экране.
- В репозитории нет скопированных знаков Bungie, Marathon или Kurppa Hosk.
