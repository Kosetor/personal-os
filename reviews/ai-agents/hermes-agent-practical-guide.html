Суть материала

Hermes Agent — open-source агентный фреймворк от Nous Research, который запускается в терминале, нативном десктоп-приложении, в мессенджерах и IDE. Он относится к той же категории, что Claude Code, OpenAI Codex или OpenClaw: автономные агенты, которые с помощью вызова инструментов (tool calling) выполняют задачи на вашей системе. Документация выделяет пять отличительных свойств:

  • Самосовершенствование через навыки — агент сохраняет повторно используемые процедуры в виде skills и подгружает их в будущие сессии.
  • Постоянная память между сессиями — запоминает пользователя, предпочтения, окружение и извлечённые уроки; поддерживаются сменные бэкенды памяти.
  • Мультиплатформенный gateway — один и тот же агент работает через Telegram, Discord, Slack, WhatsApp, iMessage, Signal, Matrix, Teams, Email и другие платформы с полным доступом к инструментам, а не только к чату.
  • Провайдер-агностичность — поддерживаются 20+ провайдеров (OpenRouter, Anthropic, OpenAI, Google, DeepSeek, xAI, локальные модели и др.), модель можно менять прямо в ходе работы.
  • Профили и расширяемость — несколько изолированных инстансов агента, а также плагины, MCP-серверы, cron, вебхуки и темы.

Установка описывается одной командой: curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash — скрипт ставит uv, Python, виртуальное окружение и лаунчер. Далее: hermes setup (мастер настройки), hermes (интерактивный чат), hermes chat -q "…" (разовый запрос), hermes doctor (проверка здоровья).

Ключевое для понимания — как устроена память агента. Схема ниже обобщает слои, описанные в документации:

Контекст сессиипеременный, сжимается, /compress
→
Постоянная памятьmemory_enabled, user profile, /memory
→
Навыки SKILL.mdпроцедуры, /learn, curator
→
Профили~/.hermes/profiles/<name>, изоляция

Почему это важно

ИИ-агенты перестали быть игрушкой: они выполняют реальную работу — пишут код, ведут переписку, собирают данные. Документация Hermes важна тем, что описывает зрелую архитектуру, а не демо: тут есть постоянная память, процедурные навыки, фоновая автоматизация, интеграции и продуманная модель безопасности — всё, чего не хватает простым «чат-ботам с API».

  • Открытый код и локальный запуск — данные и ключи остаются у вас; можно работать с локальными моделями, не отправляя контекст в чужие API.
  • Один агент на многих поверхностях — та же кодовая база крутит CLI, десктоп, веб-дашборд и мессенджеры; нет дублирования логики.
  • Самосовершенствование — навыки превращают удачный опыт в переиспользуемую процедуру, а curator обслуживает их жизненный цикл без ручного вмешательства.
  • Отсутствие привязки к вендору — смена модели или провайдера не ломает агента, пул ключей ротируется автоматически.
  • Для Personal OS это образец — как документировать собственные агентные конвейеры и как встроить агента в статический сайт: генерация обзоров, проверка ссылок, cron-доставка.

Практическое применение

Разберём, что из документации можно применить уже сегодня. Ниже — только то, что подтверждено локальной документацией; неподтверждённые детали помечены как интерпретация.

  • Установка и запуск: hermes setup → выбор провайдера и модели → hermes. Проверка: hermes doctor.
  • Конфигурация: настройки — в ~/.hermes/config.yaml через hermes config set section.key value; секреты и API-ключи — только в ~/.hermes/.env. Изменения инструментов вступают в силу на новом сеансе (/reset), чтобы не ломать кэш промпта.
  • Постоянная память: секция memory в конфиге (memory_enabled, user_profile_enabled, provider, write_approval); незаписанные факты копятся в очереди — команда /memory pending|approve|reject. Интерпретация: в обсуждениях проекта фигурируют файлы-хранилища MEMORY.md/USER.md и SOUL.md/HERMES.md с лимитами символов — локальная документация на момент проверки эти имена напрямую не подтверждает, точные лимиты сверяйте с актуальными docs.
  • Навыки (skills): навык — это SKILL.md с frontmatter (имя, описание, триггеры). Создание: /learn <source> из чата, директории или URL; управление: /skills, hermes skills. Поддержку порядка ведёт curator.
  • Инструменты и toolsets: hermes tools включает/выключает наборы — terminal, file, web/search, browser, code_execution, vision, memory, session_search, delegation, cronjob, kanban и др.; есть минимальный набор safe для «запертых» сессий.
  • MCP-интеграции: встроенный MCP-клиент — серверы прописываются в mcp_servers (stdio через command или HTTP через url), инструменты на старте обнаруживаются и регистрируются с префиксом mcp_<server>_<tool>, затем автоматически инъектируются во все платформенные toolsets. Перезагрузка: /reload-mcp.
  • Messaging gateways: Telegram, Discord, Slack, WhatsApp и др.; из CLI сессию можно передать в мессенджер командой /handoff, состояние платформ смотрит /platforms, приостановка — /platform pause.
  • Cron и фоновые задачи: durable-планировщик через cronjob-инструмент, hermes cron или /cron; расписания — длительности ("30m"), фразы ("every monday 9am"), cron-выражения или ISO-метки; у каждого задания свой model, skills, workdir, цепочки через context_from.
  • Профили: независимые инстансы в ~/.hermes/profiles/<name>/ с собственными конфигами, сессиями, навыками и памятью.
  • Безопасность: маскировка секретов в выводе инструментов включена по умолчанию (security.redact_secrets); режимы одобрения команд — approvals.mode: smart (по умолчанию), manual, off; разовый обход — hermes --yolo. Сброс накопленных разрешений: очистить command_allowlist.

Ограничения и риски

  • Живой проект, документация догоняет код: функции добавляются быстро; внутри сессии авторитетен /help, а локальная копия руководства может отставать от репозитория.
  • Фоновые делегации не durable: delegate_task с background=true живёт в процессе родителя — при его выходе дочерняя задача теряется. Для работы, которая должна пережить процесс, нужны cronjob или terminal(background=true).
  • YOLO ≠ безопасность: approvals.mode: off или --yolo обходит запросы одобрения, но не отключает маскировку секретов — это независимые механизмы; всё равно режим off не рекомендуется.
  • Секреты: нарушение инварианта «ключи в .env, настройки в config.yaml» — частая причина утечек; маскировка не заменяет гигиену хранения.
  • Кэш промпта диктует правила: менять инструменты и системный промпт посреди разговора нельзя (ломается кэширование) — отсюда необходимость /reset; это надо закладывать в сценарии автоматизации.
  • Зависимости MCP: без установленного Python-пакета mcp поддержка молча отключается; для серверов на npx/uvx нужны Node.js и uv.
  • Сторонний код: MCP-серверы и gateway-платформы — внешние компоненты с доступом к вашим инструментам; их нужно выбирать осознанно.
  • Непроверенные детали: имена файлов памяти (MEMORY.md, SOUL.md) и их лимиты символов в локальной документации не подтверждены — это интерпретация, требующая сверки с официальным сайтом.

Что можно сделать в Personal OS / Hermes

Практическая интерпретация: как превратить этот обзор в работающий конвейер на нашем сайте.

  1. Поднять агента: установить Hermes по однострочнику, прогнать hermes setup и hermes doctor, выбрать провайдера.
  2. Настроить память: включить memory_enabled и user_profile_enabled, настроить write_approval, регулярно разбирать очередь /memory.
  3. Создать навык обзоров: обучить агента процедуре «источник → карточка → HTML-обзор» через /learn или вручную оформить SKILL.md с триггерами — тогда каждый новый обзор делается по проверенному шаблону.
  4. Запустить cron: еженедельная задача проверки битых ссылок на сайте и генерации карточек новых источников с доставкой в выбранный канал.
  5. Подключить MCP-сервер: например, файловый сервер для репозитория Personal OS или базы Obsidian, чтобы агент читал и обновлял заметки нативно.
  6. Включить Telegram-gateway: доступ к агенту с телефона — «скинь список просроченных карточек» из любого места.
  7. Включить curator: curator.enabled: true — навыки не протухают, устаревшие архивируются с бэкапом, ничего не теряется.
  8. Проверить безопасность: оставить security.redact_secrets: true и approvals.mode: smart, ключи держать в .env, не коммитить ~/.hermes в репозиторий сайта.
